**Link Validator** is the Antora-facing half of outbound link checking: on `contentClassified` it collects links from classified pages, checks them via https://github.com/antora-supplemental/asciidoc-link-validator[`@antora-supplemental/asciidoc-link-validator`] (rate limits, cache, surgical invalidation), logs one summary line (not per-link 429 noise), and on `sitePublished` writes:

* `link-validator/report.json` (+ markdown)
* A triage HTML page titled **Link Validator** (filter to current page, newly-invalid toggle, copy / mailto)
* Footer partial `ui/partials/footer-link-validator.hbs`

For CLI / non-Antora AsciiDoc trees, use the core package directly.

Docs hub (when wired): https://docs.antora-supplemental.org/link-validator/[Explore the docs →]

== Install

Primary (GitHub SemVer URL — recommended for Antora / pnpm):

[source,bash]
----
pnpm add -D github:antora-supplemental/link-validator#v0.2.2
----

Alternate (track main):

[source,bash]
----
pnpm add -D github:antora-supplemental/link-validator#main
----

Optional npm (not required): `pnpm add -D @antora-supplemental/link-validator` if/when published later.

Consumer topic: `link-validator`.

== Playbook

[source,yaml]
----
antora:
  extensions:
    - require: '@antora-supplemental/link-validator'
      concurrency: 8
      timeoutMs: 10000
      softFail403: true
      failLevel: none
      reportEmail: support@devcentr.org
      suppressionsFile: .antora-link-suppressions.yml
      baselinePath: .link-baseline.json
      checkImages: true
      cacheEnabled: true
      cachePath: .link-check-cache.json
      # invalidateSources / invalidateUrls — or env LINK_VALIDATOR_INVALIDATE_*
      # CI: pass GITHUB_TOKEN in env (not here)
      # Nightly full refresh: cacheBypass: true or LINK_VALIDATOR_CACHE_BYPASS=true
      # Optional override; omit for auto (destination when host clusters dominate)
      # groupingDefault: byDestination
      ciTrigger:
        enabled: true
        provider: github
        # Public workflow-dispatch URL or thin proxy — NEVER put a token in the playbook/HTML
        dispatchUrl: https://example.com/link-validator-proxy/dispatch
        statusUrl: https://example.com/link-validator-proxy/status
        ref: main
        label: Check now (CI)
        pollIntervalMs: 5000
----

After generate, open `/link-validator/` on the site.

=== Triage UI

* **Group by** destination URL, source page, status, or host (Auto uses core default heuristic).
* **Check now (CI)** when `ciTrigger.enabled` + `dispatchUrl` are set; polls for an updated `report.json`.
* **Email report** (percent-encoded mailto) and **Copy report** always available as fallback.
* Prior report history lists entries from `meta.reportHistory`. The extension **auto-populates** this array from archived `report-*.json` files on each site publish (`reportHistoryLimit`, default 20) — no manual edits.

=== Security note (CI trigger)

The published site must store only a **public** dispatch URL or a **thin proxy** that holds the GitHub/GitLab token server-side. Do not embed PATs or `GITHUB_TOKEN` in static HTML or the playbook fragment shipped to browsers.

== Multi-repo hub dispatch (recommended)

Aggregated sites should rebuild when a content source changes outbound links — without polling and without embedding tokens in the playbook.

* **Hub (subscriber):** listen for `repository_dispatch` type `link-cache-invalidate` on the playbook repo; map payload `sources` / `urls` to env `LINK_VALIDATOR_INVALIDATE_SOURCES` / `LINK_VALIDATOR_INVALIDATE_URLS` on the Antora build step (v0.2.2+).
* **Sources (callers):** after `docs/**` changes, dispatch into the hub with org secret `DOCS_HUB_DISPATCH_TOKEN` (Dev-Centr: reusable workflow `dev-centr/agent-rules/.github/workflows/docs-hub-link-cache-invalidate-dispatch.yml`).
* **Reference:** https://docs.devcentr.org/docs-site/notify-docs-hub-link-changes.html[Dev-Centr hub how-to] and https://docs.antora-supplemental.org/site-rebuild/[site rebuild architecture].

Same star pattern as `docs-source-updated` / `extension-updated`; use `link-cache-invalidate` when you want surgical cache bypass plus deploy.

== CLI / CI

Multi-provider CI templates ship with the **core** package (`asciidoc-link-validator`). This Antora package runs CI tests on push/PR and creates a GitHub Release on version tags (primary distribution: GitHub SemVer URL pin) (see `.github/workflows/`).

Optional write-back (baseline commit / issue upsert): `.github/workflows/link-validator-writeback.yml`.

== Thin CI dispatch proxy

The triage **Check now (CI)** button must call a *public* URL. Ship a thin proxy that holds the GitHub token server-side:

* Example (Express + Cloudflare Workers): https://github.com/antora-supplemental/asciidoc-link-validator/tree/main/examples/dispatch-proxy[`asciidoc-link-validator/examples/dispatch-proxy`]
* Set playbook `ciTrigger.dispatchUrl` / `statusUrl` to that proxy's `/dispatch` and `/status`.
* **Never** put `GITHUB_TOKEN` in static HTML.

Env vars and wiring: see the proxy README in that folder.
